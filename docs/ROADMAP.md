# 정확도 개선 로드맵

## 실제 영상에서 예상되는 약점

- **공 검출**: 지금은 움직임 + 색 기반입니다. 모션 블러가 심하거나, 공이 흰 선·밝은 옷 위를 지나거나, 먼 코트에서 공이 2~3픽셀이면 놓칠 수 있습니다.
- **먼 코트 깊이 오차**: 카메라 반대편 베이스라인 근처는 1픽셀이 약 15cm입니다. 1080p 이상, 높은 촬영 위치가 중요합니다. 서버는 현재 가로 1280px로 줄여 분석하므로(`pipeline.MAX_WIDTH`) 판정 정확도를 위해 원본 해상도 분석 옵션을 추가해야 합니다.
- **공기 저항 미반영**: 포물선 모델에 항력이 없어서 빠른 서브는 속도가 실제보다 낮게, 궤적 끝부분이 조금 어긋날 수 있습니다. 항력 계수를 넣은 비선형 피팅으로 보완 가능합니다.
- **네트 터치(렛)**: 공이 네트에 스친 서브는 영상만으로 구분이 어렵습니다. 현재는 일반 서브처럼 판정합니다.
- **카메라 흔들림**: 폰 분석(`pipeline.py`)은 고정 카메라를 가정합니다. 중계 분석(`broadcast.py`)은 배경 특징점으로 팬·줌을 보정하므로, 흔들리는 폰 영상도 같은 방식으로 옮길 수 있습니다.
- **렌즈 왜곡**: 광각 중계 화면은 가까운 베이스라인이 휘어 보여 호모그래피 하나로는 코트가 다 맞지 않습니다(실측 480p 지역 방송에서 가장자리 20px 이상). 방사 왜곡 계수를 코트 맞춤에 함께 추정해야 합니다.
- **포인트 사이 구분**: 공이 1.2초 이상 안 보이면 포인트가 끝난 것으로 봅니다. 공 줍기, 다음 서브 전 공 튀기기가 가짜 랠리로 잡힐 수 있어서, 서브 동작 검출(선수 포즈)로 포인트 시작을 확정하는 게 좋습니다.

## 다음 단계

1. **실제 영상 수집과 라벨링**: 준호 님 경기 영상 몇 개에서 바운스 위치와 인/아웃, 점수를 기록해 평가 세트로 씁니다.
2. **학습형 공 검출기**: TrackNet 계열(연속 3프레임 → 공 위치 히트맵) 모델을 공개 데이터셋 + 우리 영상으로 학습해 `BallDetector` 자리에 넣습니다.
3. **바운스 분류기 보강**: 지금의 규칙 기반 분류를 궤적 특징 기반 분류기로 보완합니다.
4. **온디바이스 분석**: 모델이 안정되면 Core ML / TFLite로 옮겨 서버 없이 폰에서 분석합니다. 그때는 촬영하면서 실시간 콜도 가능합니다.
