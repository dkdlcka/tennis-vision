# Tennis Vision

폰으로 찍은 테니스 경기 영상을 분석해서 **공 궤적 추적 → 매 바운스 인/아웃 판정 → 점수 자동 기록**까지 해 주는 모바일 앱입니다.

```
[모바일 앱 (Expo)]  영상 선택/촬영 → 코트 모서리 확인 → 업로드 → 결과 보기
        │  HTTP
[분석 서버 (Python)] 코트 인식 → 공 검출·추적 → 3D 궤적 복원 → 바운스/타구 → 판정 → 점수
```

## 어떻게 판정하나

1. **코트 인식** (`court_detect.py`): 흰 선을 찾아 베이스라인·사이드라인 후보를 만들고, 실제 코트 규격(ITF)을 가장 잘 덮는 조합으로 호모그래피를 구합니다. 실패하면 앱에서 모서리 4개를 손으로 맞춥니다.
2. **카메라 복원** (`court.py` `CourtCamera`): 코트의 직각 관계로 초점거리와 카메라 위치·자세를 계산합니다. 이것 덕분에 화면 속 공을 3D로 되돌릴 수 있습니다.
3. **공 검출·추적** (`ball.py`): 배경 차분 + 프레임 차분으로 움직이는 작은 물체를 찾고, 공 색(연두)과 밝기로 그림자·잔상을 걸러낸 뒤 궤적으로 잇습니다.
4. **바운스/타구 검출** (`events.py`): 공은 두 접촉(라켓 또는 바닥) 사이에서 포물선을 그립니다. 궤적을 여러 개의 3D 포물선으로 나눠 맞추고(연속성 조건 포함), 끊어진 지점에서 진행 방향이 유지되면 **바운스**, 반대로 바뀌면 **타구**로 봅니다. 공이 화면 밖으로 사라지기 직전의 착지도 궤적을 연장해 잡습니다.
5. **인/아웃 판정** (`scoring.py` `judge_point`): 바운스 지점을 코트 좌표로 옮겨, 서브는 대각 서비스 박스, 랠리는 상대 코트(단식/복식)와 비교합니다. 라인에 닿으면 인이고, 라인까지 몇 cm였는지도 기록합니다.
6. **포인트·점수** (`scoring.py`): 바운스 순서로 포인트를 결정합니다. 서브 폴트/더블 폴트, 아웃, 같은 코트에 두 번 바운드(네트에 걸려 떨어진 공 포함), 받지 못한 공(위너/에이스). 점수는 듀스·애드, 노애드, 타이브레이크, 서브 순서, 코트 체인지까지 따라갑니다.

결과에는 포인트별 기록, 바운스 목록(인/아웃, 라인과의 거리), 서브 속도, 샷 속도, 네트 통과 높이, 선수별 통계가 들어갑니다.

## 실행

### 분석 서버

```bash
cd server
python3 -m pip install -e '.[dev]'
uvicorn tennis_vision.api:app --host 0.0.0.0 --port 8000
python3 -m pytest            # 합성 경기 영상으로 전체 파이프라인 검증
tennis-analyze match.mp4 --out report.json   # 앱 없이 바로 분석
```

### 앱

```bash
cd app
npm install
npx expo start
```

앱 홈 화면의 "분석 서버"에 서버 주소(같은 와이파이의 PC면 `http://<PC IP>:8000`)를 넣으면 됩니다. `expo-video`, `react-native-svg` 등 네이티브 모듈을 쓰므로 Expo Go 대신 개발 빌드(`npx expo run:ios` 또는 `eas build --profile development`)가 필요할 수 있습니다.

## 촬영 가이드

- 한쪽 베이스라인 뒤 높은 곳(펜스 위, 삼각대 2m 이상)에 폰을 고정합니다.
- 코트 네 모서리가 모두 화면에 들어오게 가로로 찍습니다.
- 60fps, 1080p 이상을 권장합니다. 공이 작게 찍힐수록 먼 코트의 판정 오차가 커집니다.

## 현재 정확도와 한계

합성 경기 영상(압축된 720p 30fps, 선수·그림자·노이즈 포함)으로 검증했습니다.

- 바운스 위치 오차: 가까운 코트 약 5~10cm, 먼 코트 약 10~25cm
- 테스트 경기의 서브 인, 폴트, 아웃, 투바운드, 에이스 판정과 최종 점수가 모두 정답과 일치

실제 경기 영상에서는 아직 검증하지 못했습니다. 예상되는 약점과 다음 단계는 [docs/ROADMAP.md](docs/ROADMAP.md)에 정리했습니다. 특히 공 검출기를 학습형 모델(TrackNet 계열)로 바꾸는 것이 가장 큰 개선이 될 것입니다. `ball.py`의 `BallDetector`가 교체 지점입니다.
